1

Каркас интерфейса

UI

Начинаем с чисто визуальной раскладки: Column с полем результата и сеткой кнопок 4×4. Кнопки ничего не делают — onClick = { }.

@Composable
fun CalcButtonV1(label: String, modifier: Modifier = Modifier) {
    Button(
        onClick = { },
        modifier = modifier.fillMaxHeight(),
        shape = MaterialTheme.shapes.medium
    ) {
        Text(text = label, fontSize = 24.sp)
    }
}

На этом этапе экран выглядит как калькулятор, но не считает — это чистый макет.

Добавление состояния и логики вычислений

Логика

Вводим четыре переменные состояния через remember { mutableStateOf(...) }:

  • displayText — то, что показано на экране / вводится сейчас
  • operand1 — первое число операции
  • pendingOperator — ожидающий применения оператор
  • resetDisplayOnNextInput — флаг «следующая цифра начинает новое число»

Реализуем обработчики: onDigit, onDecimal, onClear, onOperator, onEquals, и функцию applyOperator для четырёх арифметических действий. Также добавлена кнопка =, которой не хватало в исходной раскладке.

fun applyOperator(op1: Double, op2: Double, operator: String): Double {
    return when (operator) {
        "+" -> op1 + op2
        "-" -> op1 - op2
        "×" -> op1 * op2
        "÷" -> if (op2 != 0.0) op1 / op2 else Double.NaN
        else -> op2
    }
}
3

Баг: цепочка операций склеивала цифры

Баг Исправлено

Симптом: ввод 2 + 3 = давал 25 вместо 5.

Причина: после нажатия оператора экран не сбрасывался. Следующая цифра дописывалась к старому числу: "2" + "3" → "23".

2 → displayText = "2"
+ → operand1 = 2, displayText остаётся "2" // ошибка
3 → displayText = "2" + "3" = "23" // должно быть "3"

Исправление: в onOperator теперь выставляется resetDisplayOnNextInput = true, а onDigit проверяет этот флаг перед дописыванием цифры.

До
fun onOperator(op: String) {
    ...
    pendingOperator = op
}
После
fun onOperator(op: String) {
    ...
    pendingOperator = op
    resetDisplayOnNextInput = true
}

Форматирование результата (округление)

Баг Исправлено

Симптом: 7 ÷ 9 выводил 0.7777777777777778 — полная точность Double, не помещающаяся на экран.

Исправление: округляем до 8 знаков после запятой и убираем лишние нули на конце. Используем Locale.US, чтобы разделитель дробной части всегда был точкой независимо от локали устройства.

fun formatResult(value: Double): String {
    if (value.isNaN()) return "Error"
    if (value == value.toLong().toDouble()) return value.toLong().toString()

    val rounded = String.format(Locale.US, "%.8f", value)
        .trimEnd('0')
        .trimEnd('.')
    return rounded
}
7 ÷ 9 = 0.7777777777777778
→ "%.8f" → "0.77777778"
→ обрезка нулей: не требуется
→ итог на экране: 0.77777778
5

Адаптивный размер шрифта

Баг Исправлено

Симптом: даже после округления длинные числа (например 0.77777778) накладывались друг на друга при шрифте 64.sp — maxLines = 1 сам по себе не решает проблему переполнения ширины.

Исправление: размер шрифта зависит от длины строки, плюс TextOverflow.Ellipsis как страховка на случай ещё более длинных чисел.

Text(
    text = displayText,
    fontSize = when {
        displayText.length > 12 -> 32.sp
        displayText.length > 9  -> 40.sp
        displayText.length > 6  -> 52.sp
        else -> 64.sp
    },
    textAlign = TextAlign.End,
    overflow = TextOverflow.Ellipsis,
    maxLines = 1
)

Итог: короткие числа остаются крупными (64.sp), а длинные результаты вроде 0.77777778 уменьшаются до 40.sp и помещаются в одну строку без наложения символов.

Итоговое состояние

После пяти этапов калькулятор:

  • Выполняет + − × ÷ с поддержкой цепочки операций (5 + 3 + 2 =)
  • Корректно сбрасывает ввод после оператора и после =
  • Показывает Error при делении на ноль вместо краша
  • Округляет дробные результаты до 8 знаков вместо полной точности Double
  • Масштабирует шрифт под длину числа, чтобы избежать наложения цифр
